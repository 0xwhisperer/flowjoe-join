FlowJoe gives you control over where your work lives, what Joe can read, and what you share.

- **Local-first work:** keep your tree, notes and imported media on your computer, with a Workspace Folder you can back up yourself.
- **Controlled sharing:** choose what guests can access through your computer; Private nodes stay out of browser sharing.
- **AI access controls:** choose Joe's provider and permissions, and use Private or Hidden-from-Joe protection for sensitive content as described below.
- **Encrypted portable backups:** protect an exported package with its own password, including the Private content you explicitly choose to include.

Each control has a specific purpose. The details below explain what it protects and what to check when sharing or moving work.

## Where your work lives

Normal desktop work stays in app storage, or in a **Workspace Folder** you choose. A Workspace Folder keeps the Flow and its shared media in files you can back up or sync with your own tools.

You choose which content guests can access, and sharing sends that permitted content through the owner's computer. Remote sharing can use a Cloudflare tunnel, with encryption between each computer and Cloudflare. Cloudflare decrypts traffic before forwarding it, so this is not end-to-end encryption between owner and guest.

AI features send the context they need to your selected provider; that provider's account and data policies apply. Web browsing and link previews contact the websites you use.

See [Workspace folders](/workspaces/folders), [Sharing](/workspaces/sharing-and-presenting), and [Token usage](/joe/token-usage).

## What is encrypted today

| What you save | Protection in the current release |
| --- | --- |
| A package exported with **Protect package with a password** | The complete selected package is encrypted, including admitted Private content and included media/history. |
| An ordinary `.fj`, JSON, or repository export | Included content is readable outside FlowJoe. A Private node's password does not encrypt these files. |
| Private content saved on this computer | The password controls access inside FlowJoe. Saved content, media, autosaves and local history are not encrypted by that node password. |
| Supported API keys saved by the desktop app | OS-backed encryption when secure storage is available; a session-only choice when it is unavailable. |
| API keys in a standalone browser | Session-only by default. Saving a key on this computer requires explicit consent to plain-text storage. |

<Note>
Encrypted storage for Private nodes is still being developed and is not enabled in the current release. Locking a node again does not encrypt copies already saved on this computer. Use your computer's disk protection and password-protected package backups for sensitive work.
</Note>

## API keys

On desktop, supported keys are encrypted using the operating system’s secure-storage service when available and saved in FlowJoe’s app data. If that service fails or provides only weak protection, you can enter a key **for this session only** while the existing saved key stays intact. You can also try opening secure storage again. FlowJoe never silently saves a desktop key as plain text.

In a standalone browser, new keys default to **For this session only**. They disappear on refresh or close. To keep one, you must explicitly choose **Save on this computer as plain text**; anyone or anything with access to the browser’s storage could read it. If a plaintext key already exists, Cancel keeps it, and you can choose to keep the saved copy or remove it and use the key for this session.

Desktop temporary keys last until you quit FlowJoe. After restarting, enter the key again before tasks using it can run; any previously saved encrypted key remains available instead. Remove is an explicit deletion. Including a key in an export still requires the separate opt-in.

Keys appear masked in Settings. Use the eye button to reveal or copy them. Keys are excluded from portable exports by default; the export dialog lets you explicitly include an OpenAI key. Review that option before sharing a package.

## Private and Hidden-from-Joe nodes

**Private** nodes protect access in the app with a password. Their contents are excluded from the shared Workspace Folder and browser guests. You can explicitly include individual Private nodes in a portable export or repository after entering their passwords and reading the warning; otherwise their contents stay on your computer. Unlocking one for yourself does not give Joe access to its contents.

A Private folder inside a Git repository stays out of every commit and push. The one exception is your own choice: when you make a branch a repository you can include a Private node after entering its password and reading the warning. Its contents then go into the repository unencrypted, readable by anyone who opens the files outside FlowJoe, and Git keeps them in the history. Only the lock’s check value travels with it, never the password, so it stays locked inside FlowJoe for whoever clones it. It stays included for whoever clones it. If you later remove its password and set a new one, it stays out of Git from then on. See [Repositories](/tree/repositories#make-a-branch-a-repository).

FlowJoe runs Git with its own fixed settings, so a repository can't make your computer run a program. Settings that would run one, such as a filter, a merge or diff tool, a signature checker or a credential helper, are switched off; when a repository's own settings name such a program anyway, FlowJoe refuses that step instead. Large files stored with Git LFS are downloaded and sent by FlowJoe itself, never by a program the repository names. Your GitHub sign-in goes only to the repository's own host when FlowJoe asks where a large file is or where to send it, never to the server the file then comes from or goes to. A push sends large files only after the Private-folder check has passed, and never a file from a Private folder you kept out. FlowJoe checks the current Private folders again after the first-push review. Each push sends the exact commits it checked; a commit or tag changed during the push waits for the next one. See [Repositories](/tree/repositories#large-files-git-lfs).

Your Joe chats, picture history, transcripts, undo notes history and Memories go into a repository only when you choose them for that repository; each choice is off to begin with. Chosen history goes to anyone who can read the repository, and Git keeps it even if you later turn the choice off. A conversation or transcript you keep on this computer, and the history of a Private folder you did not include, never go in. See [History in the repository](/tree/repositories#history-in-the-repository).

**Hidden from Joe** seals a node’s contents from Joe while leaving them available to you. Sealed node names and positions can still appear in Joe’s outline, so keep secrets out of names. A media read still waiting for its result checks these protections again before returning it. Hidden from Joe is a preference for your own Joe: a guest’s Joe can still read content that guest is allowed to see. Neither setting recalls information already sent in an earlier message.

For an encrypted portable copy of Private work, explicitly select each Private node, confirm its password, and enable **Protect package with a password**. Included nodes also keep their separate FlowJoe access locks. Those node locks control access inside the app; they do not encrypt the saved text or media on this computer. Without package encryption, an exported file's included content is readable outside FlowJoe.

Existing virtual slots can remain together inside one unlocked Private area for your own use; Joe and guests still cannot read their Private master. Making separate branches Private treats each branch as a separate area and converts pointers between them to real copies. Moves that would separate a retained pair across a Private boundary are refused without moving any of the selection. See [Virtual slots](/gallery/virtual-slots#making-a-node-private).

## Review changes

Joe normally proposes Flow changes for you to approve, reject, or revise. Scheduled tasks and connected agents can apply changes under permissions you authorize. See [Proposals & approval](/joe/propose-approve) and [Automations](/joe/automation) before enabling automatic work.

## Encrypted backups

Select **Protect package with a password** when exporting to encrypt the entire exported file, including any Private nodes, media and history you explicitly chose to include. Private nodes start excluded; entering a node password to include one does not turn on package encryption.

The recipient needs the **package password** to import the file. Included Private nodes keep their separate **node passwords** and remain locked after import. Unlocking the package does not unlock those nodes.

Package encryption protects that exported copy. Import restores its contents into FlowJoe’s normal storage; it does not create an encrypted live Flow or Workspace Folder. Keep using your computer’s disk protection. The outer file name and file size remain visible.

To preserve Private work off-device, explicitly include each Private node and its needed history in a full, password-protected package, and keep its package password and separate node passwords safe. A Workspace folder copy alone leaves that owner-only content on the original computer and cannot recover it if the computer is lost. See [Backup contents and exclusions](/guides/portability#what-each-copy-preserves).

Full packages saved through a file-saving window use streaming encryption, including packages above 2 GiB. Use a current FlowJoe version to open them. Data-only exports, browser download fallbacks and earlier backups retain their memory limits.

Keep the package password safe: FlowJoe cannot recover a package if you lose it. See [Password-protected packages](/portability/export-import#password-protected-packages) for the export and import steps.



### GitHub access when sharing a Flow

The owner can ask Joe to list and clone all repositories accessible to the owner’s signed-in GitHub account, including private GitHub repositories. A guest can list or clone that account’s public repositories, plus repositories already visible in their shared Flow even if private on GitHub. Other private GitHub repositories are withheld. A View guest can read the permitted list; creating or cloning a repository node requires Edit access to its destination. The owner’s computer rechecks this access before the clone is attached.

Joe uses named FlowJoe repository actions. Downloads, commits, pushes, merges and branch changes require an approval slot on every brain, including external assistants with ordinary edit autoapproval. GitHub credentials remain on the owner’s computer and are never sent to Joe or guests. A repository marked private on GitHub is different from a password-protected **Private node** in a Flow: the Flow’s normal Private and sharing rules still apply.
