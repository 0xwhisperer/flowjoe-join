FlowJoe puts your work on your computer and gives you clear controls for bringing AI and collaborators into it.

## Where your work lives

Normal desktop work stays in app storage, or in a **Workspace Folder** you choose. A Workspace Folder keeps the Flow and its shared media in files you can back up or sync with your own tools.

Sharing deliberately sends permitted content to guests through the owner’s computer. Remote sharing can use a Cloudflare tunnel. AI features send the context they need to the selected provider; the provider’s account and data policies apply. Web browsing and link previews also contact websites.

See [Workspace folders](/workspaces/folders), [Sharing](/workspaces/sharing-and-presenting), and [Token usage](/joe/token-usage).

## API keys

On desktop, supported keys are encrypted using the operating system’s secure-storage service when available and saved in FlowJoe’s app data. In a standalone browser, or when secure storage is unavailable, keys use local browser storage with weaker protection.

Keys appear masked in Settings. Use the eye button to reveal or copy them. Keys are excluded from portable exports by default; the export dialog lets you explicitly include an OpenAI key. Review that option before sharing a package.

## Private and Hidden-from-Joe nodes

**Private** nodes protect access in the app with a password. Their contents stay on the owner’s computer and are excluded from the shared Workspace Folder and browser guests. Unlocking one for yourself does not give Joe access to its contents.

A Private folder inside a Git repository stays out of every commit and push. The one exception is your own choice: when you make a branch a repository you can include a Private node after entering its password and reading the warning. Its contents then go into the repository unencrypted, readable by anyone who opens the files outside FlowJoe, and Git keeps them in the history. Only the lock’s check value travels with it, never the password, so it stays locked inside FlowJoe for whoever clones it. It stays included for whoever clones it. If you later remove its password and set a new one, it stays out of Git from then on. See [Repositories](/tree/repositories#make-a-branch-a-repository).

FlowJoe runs Git with its own fixed settings, so a repository can't make your computer run a program. Settings that would run one, such as a filter, a merge or diff tool, a signature checker or a credential helper, are switched off; when a repository's own settings name such a program anyway, FlowJoe refuses that step instead. Large files stored with Git LFS are downloaded and sent by FlowJoe itself, never by a program the repository names. Your GitHub sign-in goes only to the repository's own host when FlowJoe asks where a large file is or where to send it, never to the server the file then comes from or goes to. A push sends large files only after the Private-folder check has passed, and never a file from a Private folder. See [Repositories](/tree/repositories#large-files-git-lfs).

**Hidden from Joe** seals a node’s contents from Joe while leaving them available to you. Sealed node names and positions can still appear in Joe’s outline, so keep secrets out of names. Neither setting recalls information already sent in an earlier message.

Private-node passwords do not encrypt all data at rest. A normal portable package can carry private content and its protection settings. Use package encryption when you need a protected backup.

## Review changes

Joe normally proposes Flow changes for you to approve, reject, or revise. Scheduled tasks and connected agents can apply changes under permissions you authorize. See [Proposals & approval](/joe/propose-approve) and [Automations](/joe/automation) before enabling automatic work.

## Encrypted backups

When exporting a **.fj** package, you can protect that package with a password. The recipient needs the password to import it. This protects the exported file; it does not encrypt the live Workspace Folder or replace your computer’s disk protection.
