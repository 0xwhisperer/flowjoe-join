The CLI has simple commands such as `show` and `search`, plus access to the running app’s **actions**.
An action is a complete request, such as reading a document or preparing an image. The **editing
verbs** are individual changes sent inside `apply` or `propose_flow_patch`; see
[node changes](/cli/node-changes), [reference and stack changes](/cli/gallery-changes), and
[Flow details and automations](/cli/flow-changes).

This page covers the current desktop bridge action surface. Availability depends on the running
build, permission level and configured services. Read the actual list with `flowjoe-cli actions`.
`get_app_state`, `query_history` and `read_history` expose current app facts and retained history.
Saved history is separate from this command’s recent-change and undo history. Read access includes
observational actions, including automation status and app help; it does not grant Flow edits.
The editing catalog can still be inspected with Read access, even though applying its verbs requires Propose access.
The CLI does not expose MCP resource listing/reading as a command; `open_reference` supplies app help.

## Catalog snapshot and permissions

On 2026-10-19, real CLI discovery against a fully provisioned desktop (history, repository,
scheduler and help services present) returned **27 actions with Propose access** and **20 with Read
access**. Both profiles included **19 observational read tools**; Read’s extra action was
`upload_attachment`, which prepares connection-local input rather than reading existing content.
Propose also exposes editing, staging, generation, file import, navigation, player control and undo.
A desktop without one of those services lists fewer actions. These action totals are separate from
the **60 editing verb names** returned by `describe_patch_protocol`: 59 distinct changes, because
`setNodeReadOnly` is an older name for `setNodeFrozen`. That catalog includes `editRepoFileText`.
Read can inspect the editing catalog but cannot apply its changes.
A second measurement later on 2026-10-19, after Joe’s [workflow hand-offs](#only-in-joes-chat) and picture search landed, returned the same totals, and a direct MCP connection was offered exactly the same actions as the CLI at both access levels.

Observational tools in both profiles were `get_flow_snapshot`, `describe_patch_protocol`,
`read_media_blob`, `get_app_state`, `query_history`, `read_history`, `get_node_neighbors`,
`search_flow`, `get_island_content`, `read_item_content`, `read_media_content`, `list_joe_memories`,
`list_scheduled_tasks`, `open_reference`, `list_recent_changes`, `get_approval_outcome` and
`read_chat_attachment`, `read_repository` and `read_repo_file`. Uploads, staging, generation, navigation, player actions and mutations are
not counted as observational reads. These are dated measurements, not permanent limits: discover
your running app’s catalog before scripting. Native Joe, external MCP and guests can have different
services and authority; an owner endpoint does not establish guest or shared-Flow support.

## Only in Joe’s chat

Joe works the same on every brain that uses Flow tools (OpenAI, Gemini, and CLI brains such as Claude, Grok, Codex and Gemini CLI). Antigravity can't use Flow tools yet; they're coming once they've been checked. His chat inside FlowJoe, whether an OpenAI or Gemini model or an installed tool such as Claude Code answering as Joe, uses most of the actions on this page, plus the FlowJoe actions below that the CLI and other assistants connected from outside cannot call. Those actions never appear in `flowjoe-cli actions` or in the tools a connected assistant is given, and asking for one by name is refused (`unknown_action` in the CLI). The last row lists tools built into some brains, not FlowJoe actions.

| In Joe’s chat | What it does |
| --- | --- |
| `find_pictures` | Ranks the pictures in part of your Flow by what they show, so Joe opens only the best matches. Needs a [TypeSafe key](/joe/token-usage#the-optional-typesafe-key); without one, Joe picks pictures by their names. |
| `request_app_workflow` | Shows a card that hands you an existing workflow: [restore a saved version](/workspaces/recovery#ask-joe-to-restore-a-version), [export a node](/portability/export-import#ask-joe-to-export-a-node), [import a Flow](/portability/export-import#ask-joe-to-import-a-flow) or [review changes made on another computer](/workspaces/recovery#ask-joe-to-review-outside-changes). You confirm in the app’s usual dialog; Joe never runs it himself. |
| `read_terminal_output`, `read_browser_tab` | Read terminal lines you shared, or keep reading a browser page you asked about in parts (the page itself still reaches every brain as context). See the note under [Read a repository file](#read-a-repository-file--read_repo_file). |
| Web search, Code interpreter | Built into some brains rather than FlowJoe actions. See [Bring Your Own Brain](/joe/byob). |

## How to run an example

For each action below, save its JSON input as `input.json`, replace `YOUR_…` placeholders with real
IDs from `flowjoe-cli show --json`, and run the command shown. No input file is needed for actions
with no inputs. All commands require FlowJoe running with Agent Bridge enabled.

Results use the CLI’s [JSON envelope](/cli/commands#results-for-scripts); the app’s response is under
`result`, with text and possibly image content blocks. A JSON-looking text block holds the action’s
data. `--json` does not turn an image into a written description. Inspect the actual result before
assuming a change succeeded. Private/hidden content remains withheld, even with `--autoapprove`.

Gallery and stack positions start at **0**. Only pass `itemIndex` for a member **inside a stack**.
Files, undo, recent-change history and retained-history and repository cursors are owned by one command’s connection.
Content-reader cursors instead bind the target, source revision and identical selectors; using one
run list is convenient, but they do not have the history reader’s session restriction. Examples using `$result`,
previous uploads or undo must be steps in one [run list](/cli/scripting), not separate invocations.
A two-minute default wait still applies **with `--autoapprove`**; the flag removes approval waiting,
not processing time. Increase it with `--wait` when needed.

## Read repository state — `read_repository`

Read the current Flow’s admitted repository status, scoped commit identities/dates, or a saved-versus-committed file comparison. This does not run commands, stage changes, check out files or edit content. Private and Hidden from Joe sources remain withheld. Commit messages and author names are withheld because they can mention hidden paths.

**Changes and approval:** Read only; no approval. Available with external Read or Propose access when the desktop repository service exists, independently of native Joe’s chat setting.

| Input | Required? | Meaning |
| --- | --- | --- |
| `repoNodeId` | Yes | Repository node ID from the current Flow snapshot. |
| `view` | Yes | `status`, `log` or `diff`. |
| `path` | For `diff` | Exact admitted repository-relative file path. |
| `diffScope` | No | `all`, `staged` or `unstaged`; staged filtering requires an existing current Changes-list baseline. |
| `limit` | No | 1–12,000 characters; default 12,000. |
| `cursor` | No | Returned continuation; repeat identical selectors in the same `run` connection. |

```json
{"repoNodeId":"YOUR_REPO_NODE_ID","view":"status"}
```

```sh
flowjoe-cli action read_repository --file input.json --json
```

**Result:** Bounded `content`, source/view, branch/history identity and HEAD provenance, character range and optional `nextCursor`. Status describes saved gallery bytes against the branch. Deleted paths without an admitted live owner are omitted. Staging is explicitly unavailable unless a matching current Changes list exists. A changed Flow, source, privacy, permission, HEAD or canceled request refuses publication.

## Read a repository file — `read_repo_file`

Choose `saved`, `draft` or `historical` explicitly. Saved reads use native Git bytes. Draft reads require the actual already-open editor model; historical reads require an already-open read-only revision model with a unique admitted current file owner. The action never opens, selects or saves an editor. An unavailable draft is never replaced with saved text.

**Changes and approval:** Read only; no approval. Reading adds no write; the separate `editRepoFileText` editing verb is reviewed before it changes a file.

| Input | Required? | Meaning |
| --- | --- | --- |
| `repoNodeId` | Yes | Current repository node ID. |
| `source` | Yes | `saved`, `draft` or `historical`. |
| `nodeId`, `entryId` | Saved/draft | Exact current gallery owner and entry identity. |
| `path`, `oid`, `revisionTreeOid` | Historical | Exact repository-relative path and identities of the retained open revision model. |
| `limit` | No | 1–12,000 characters; default 12,000. |
| `cursor` | No | Repeat the same selectors in the same `run` connection. |

```json
{"repoNodeId":"YOUR_REPO_NODE_ID","nodeId":"YOUR_NODE_ID","entryId":"YOUR_ENTRY_ID","source":"saved"}
```

```sh
flowjoe-cli action read_repo_file --file input.json --json
```

**Result:** `content`, explicit `source`, path/OID and character range; draft/historical results also identify the captured model revision. Changed file ownership, bytes, privacy, model version or session invalidates continuation. Use one run list for all pages. A fresh command starts a different session.

Which text you get depends on `source`. `saved` is the file as FlowJoe last saved it (an immutable Git blob), `draft` is unsaved typing in a repository editor tab that is already open, and `historical` is an older revision that is already open read-only. These are never substituted for one another.

To change a file, propose the separate [`editRepoFileText`](/cli/gallery-changes#change-text-in-one-repository-file--editrepofiletext) editing verb with Propose access. Reading never grants it.

Browser-page reading is not available to the CLI or any external client. Joe inside FlowJoe can read a page you explicitly ask about, and on every brain that uses Flow tools (OpenAI, Gemini, and CLI brains such as Claude, Grok, Codex and Gemini CLI) he can also keep reading it in parts. No external connection, including this CLI, can receive that approval. Model arguments, a native Joe request, or an open tab cannot supply one. A future page grant must bind this connection to an explicit user request, exact page/revision and revocation lifecycle before the action can be listed. Terminal output is likewise not offered externally: Joe’s chat in the desktop app, on every brain that uses Flow tools (OpenAI, Gemini, and CLI brains such as Claude, Grok, Codex and Gemini CLI), can read terminal lines only after you select them and press **Share with Joe** on his card ([terminal sharing](/gallery/terminal#share-terminal-output-with-joe)), and that is not available to the CLI or other Agent Bridge assistants.

## Read current app facts — `get_app_state`

Read sampled facts about this running app without changing settings or opening a dialog. These are
current observations, not historical evidence or proof that a save is durable. Missing information is
reported as unavailable. External bridge permissions describe this connection; Joe’s native chat
setting does not grant or remove this connection’s configured Read or Propose access.

**Changes and approval:** Read only; no approval.

| Input | Required? | Meaning |
| --- | --- | --- |
| `sections` | Yes | One or more unique values: `storage`, `save`, `conflicts`, `model`, `permissions`, `diagnostics` (at most six). |

```json
{"sections":["storage","save","permissions"]}
```

```sh
flowjoe-cli action get_app_state --file input.json --json
```

**Result:** Bounded, sampled section data, with explicit unavailable fields. It does not reveal
credentials or a complete settings dump. A Flow change, revoked permission or canceled request can
invalidate an in-progress read. Owner desktop facts do not establish a guest’s permissions or settings.

## Find retained history — `query_history`

Search retained records belonging to the current Flow without opening or switching Joe chats.
Accessible owners are checked before search results, snippets and counts are produced. A missing
result does not prove something never happened: coverage and retention can be partial.

**Changes and approval:** Read only; no approval.

| Input | Required? | Meaning |
| --- | --- | --- |
| `kind` | Yes | `chat`, `image`, `transcript` or `version`. |
| `query` | No | Search text, at most 200 characters. |
| `after`, `before` | No | Inclusive ISO date/time bounds. |
| `nodeId` | No | Limit to an accessible node. |
| `limit` | No | Records per page, from 1 to 30. |
| `cursor` | No | Previous `nextCursor`; repeat the same filters in the same connection. |

```json
{"kind":"chat","query":"launch decision","limit":10}
```

```sh
flowjoe-cli action query_history --file input.json --json
```

**Result:** `records` with stable `recordId`, `revision`, source details and snippets, plus explicit
coverage and continuation information. Image history provides prompt/model metadata, not image pixels.
Version history provides permitted change metadata, not raw old documents or a version restore.

## Read a retained history record — `read_history`

Read bounded historical text identified by `query_history`. It does not change the current chat,
restore a version or grant permission to edit. Historical text is evidence from its cited source.

**Changes and approval:** Read only; no approval.

| Input | Required? | Meaning |
| --- | --- | --- |
| `kind` | Yes | The query’s `chat`, `image`, `transcript` or `version` kind. |
| `recordId` | Yes | Exact ID returned by the query. |
| `revision` | Yes | Exact revision returned for that record. |
| `limit` | No | Text character budget, from 1 to 12,000. |
| `cursor` | No | Previous `nextCursor`; repeat kind, ID, revision and limit in the same connection. |

Save this as `steps.json`, using a query that returns at least one record:

```json
[
  {"action":"query_history","input":{"kind":"chat","query":"launch decision","limit":1},"saveAs":"found"},
  {"action":"read_history","input":{"kind":"chat","recordId":{"$result":"found","path":["records",0,"recordId"]},"revision":{"$result":"found","path":["records",0,"revision"]},"limit":2000},"saveAs":"page"}
]
```

```sh
flowjoe-cli run steps.json --json
```

**Result:** Bounded text with source/conversation/message citations and character coverage. When
`page` includes `nextCursor`, a later step in the same list can read the next page by repeating the
same inputs and adding `"cursor":{"$result":"page","path":["nextCursor"]}`. Only add that step when
you expect another page; an absent result reference stops the list. Do not paste a cursor into a new
CLI command. Changed sources, revisions, Flow or permissions require a fresh query.

## Read the Flow or one branch — `get_flow_snapshot`

Read names, node IDs, structure, node notes (summary), tags and permitted reference details. Omit rootId for the whole open Flow. Gallery summaries are not the files themselves; use a content reader for a document or image.

**Changes and approval:** Read only; no approval.

| Input | Required? | Meaning |
| --- | --- | --- |
| `rootId` | No | Limit to this node's subtree. |
| `maxDepth` | No | Max depth to include. |
| `includeGallery` | No | Include a light per-slot gallery summary (incl. each slot's tagIds — needed for any tag-based slot work). |
| `includeSummary` | No | Include node notes/summaries; default true. |
| `nodeCap` | No | Maximum nodes; default 2000. |

```json
{
  "rootId": "YOUR_NODE_ID",
  "includeSummary": true,
  "includeGallery": true
}
```

```sh
flowjoe-cli action get_flow_snapshot --file input.json --json
```

**Result:** A flat nodes list with parentId, index and depth, plus permitted notes, gallery data and tag dictionary. Privacy filtering and size limits apply.

**Changes and approval:** Read only; no approval.

| Input | Required? | Meaning |
| --- | --- | --- |
| `query` | Yes | The text to search for (case-insensitive substring match). |
| `limit` | No | Max results to return (default 20, max 100). |

```json

  "limit": 10
}
```

```sh

```

**Result:** Ranked matches with nodeId, matching field and excerpt, and slotIndex/itemIndex when applicable. Empty results mean no visible match.

## Read a document or note file — `read_item_content`

Read extracted text from a gallery note, text file or supported PDF/Word/ODT/PowerPoint/EPUB. Add itemIndex only for a stack member. For scanned PDFs, startPage selects a 1-based page; follow the result’s continuation guidance.

**Changes and approval:** Read only; no approval.

| Input | Required? | Meaning |
| --- | --- | --- |
| `nodeId` | Yes | The node whose gallery holds the item. |
| `slotIndex` | Yes | 0-based slot index in that node's gallery. |
| `itemIndex` | No | Only for stack slots: 0-based item index inside the stack. |
| `entryId` | No | Expected stable entry ID; a mismatch refuses the read. |
| `itemPath` | No | Nested stack indices, starting at 0; replaces `itemIndex`. |
| `startChar`, `endChar` | No | Character range starting at 0; end is exclusive. |
| `startLine`, `endLine` | No | Line range starting at 1; end is inclusive. |
| `heading` | No | Exact Markdown heading text, through the next heading. Choose characters, lines or heading, not a combination. |
| `maxChars` | No | Page budget, from 512 to 60,000. |
| `cursor` | No | Previous `nextCursor`; repeat all other inputs. |
| `startPage` | No | Only for a SCANNED PDF being read as page images: 1-based page to start from. Use it to continue through a long scan (the result tells you the next page). Omit for a normal read. |

```json
{
  "nodeId": "YOUR_NODE_ID",
  "slotIndex": 0
}
```

```sh
flowjoe-cli action read_item_content --file input.json --json
```

**Result:** Text pages include `textContent`, `source.revision`, exact `coverage`, `partial`,
`truncated` and, when more remains, `nextCursor`. Scanned PDFs can instead return page images with
page continuation guidance. For example, `{"nodeId":"YOUR_NODE_ID","slotIndex":0,"startLine":2001,"endLine":2050}`
reads those lines rather than just the beginning of the file. A changed or moved target, changed
content or revoked access refuses continuation; restart the read. A canceled read is not a successful empty result.

## Read a spreadsheet, calendar or rich document — `get_island_content`

Read one workbench reference’s structured content. Add itemIndex only for a member inside a stack.
Use `page: true` for bounded, addressed pages. An open workbench may be flushed before reading;
`source.policy` identifies `flushed` or `stored` evidence. A failed flush is reported as
`flush_unconfirmed`, rather than presenting an unsaved draft as saved content.

**Changes and approval:** Read only; no approval.

| Input | Required? | Meaning |
| --- | --- | --- |
| `nodeId` | Yes | The node whose gallery holds the island. |
| `slotIndex` | Yes | 0-based slot index in that node's gallery. |
| `itemIndex` | No | Only for stack slots: 0-based item index inside the stack. |

```json
{
  "nodeId": "YOUR_NODE_ID",
  "slotIndex": 0
}
```

```sh
flowjoe-cli action get_island_content --file input.json --json
```

Additional optional inputs:

| Input | Meaning |
| --- | --- |
| `page` | Set `true` for addressed paging. |
| `entryId`, `itemPath` | Expected entry ID and nested stack path; `itemPath` replaces `itemIndex`. |
| `listSheets` | List workbook sheet IDs, names and dimensions without cell content. |
| `sheet` | Exact workbook sheet ID or name. Omit to read workbook order. |
| `range` | Inclusive A1 range, such as `A2001:C2050`. |
| `startRow`, `endRow`, `startColumn`, `endColumn` | Alternative inclusive workbook bounds; rows start at 1, columns use letters. |
| `startBlock`, `endBlock` | Rich-document block range, starting at 0 with exclusive end; body, then headers and footers. |
| `after`, `before`, `timezone` | Inclusive calendar dates in `YYYY-MM-DD` and an IANA timezone, such as `America/Denver`; defaults to calendar timezone or UTC. No recurrence expansion. |
| `limit` | Record budget: up to 2,000 workbook cells or 200 calendar/document records. |
| `maxChars` | Character budget, from 512 to 16,000 for these pages. |
| `cursor` | Previous `nextCursor`; repeat all other inputs. |

For example, use one of these as `input.json` with the command above:

```json
{"nodeId":"YOUR_NODE_ID","slotIndex":0,"page":true,"sheet":"Sheet1","range":"A2001:C2050"}
```

```json
{"nodeId":"YOUR_NODE_ID","slotIndex":0,"page":true,"startBlock":100,"endBlock":110}
```

```json
{"nodeId":"YOUR_NODE_ID","slotIndex":0,"page":true,"after":"2026-10-01","before":"2026-10-31","timezone":"America/Denver"}
```

**Result:** `content` contains JSON text with addressed fragments, including cell/block/event
addresses, `textOffset` and `complete`. `coverage`, `summary`, `source.revision`, `partial`, `truncated`
and `nextCursor` describe the page. A long record can span pages; keep every fragment before moving
on. Repeat identical selectors with the cursor in one `run` list. A changed source or revoked target
invalidates continuation rather than silently mixing revisions.

## Read every supported editing verb — `describe_patch_protocol`

Discover the running app’s editing names and required arguments. This catalog includes optional stable entry-ID alternatives and valid theme IDs.

**Changes and approval:** Read only; no approval.

**Inputs:** none.

```sh
flowjoe-cli action describe_patch_protocol --json
```

**Result:** Protocol/version, verbs and scopes, argRules, idTargets, blobVerbs, deferred capabilities, stageMediaKinds and nodeThemes.

## Apply a group of Flow changes — `propose_flow_patch`

Send an ordered ops array of editing verbs. The simpler apply command wraps this action. validateOnly true checks without applying or queuing. A patch is atomic: a failed operation rolls back that patch. For `editRepoFileText`, validateOnly also runs the edit’s read-only file checks (the text appears once, the file or open draft is unchanged, the file is editable), and Apply checks them again.

**Changes and approval:** Changes data. Follows app approval rules unless --autoapprove; this includes deletion, memory and task review.

| Input | Required? | Meaning |
| --- | --- | --- |
| `ops` | Yes | Ordered list of `{verb, args}` editing operations. |
| `validateOnly` | No | Check without applying or queuing approval; default false. |

```json
{
  "ops": [
    {
      "verb": "setNodeSummary",
      "args": {
        "nodeId": "YOUR_NODE_ID",
        "value": "Next steps: review the draft."
      }
    }
  ]
}
```

```sh
flowjoe-cli action propose_flow_patch --file input.json --json
```

**Result:** Applied operation results, validation errors or a pending approval. The CLI normally waits for that approval to settle.

## Prepare content for the gallery — `stage_media`

Prepare new content without placing it. Supply exactly one source: text, dataUrl or attachmentId. Raw document text and SVG text are supported; MIME must match kind. Raw media staging is limited to 10 MB. An attachmentId must come from this connection’s upload_attachment. Explicit nodeId chooses the intended destination; omitted uses the selected node.

**Changes and approval:** Prepares content; no Flow edit approval until placement. Requires an available staging capability.

| Input | Required? | Meaning |
| --- | --- | --- |
| `kind` | No | Media kind; defaults to image (or document when text is given, unless mimeType is image/svg+xml → image). Choices: image, pdf, document, audio, video, spreadsheet, rich-document, calendar. |
| `dataUrl` | No | Source A: `data:MIME;base64,…` (at most 10 MB). |
| `attachmentId` | No | An ID returned by upload_attachment in this same connection. |
| `text` | No | Source C: raw text/markdown/csv/json (kind document) OR raw SVG markup (kind image, mimeType image/svg+xml) — the app encodes + sanitizes it; do NOT base64 it yourself. |
| `mimeType` | No | With text: the document flavor (default text/markdown) or image/svg+xml for SVG markup. |
| `title` | No | Optional entry title. |
| `nodeId` | No | Intended destination node; omitted means the currently selected node. |

```json
{
  "nodeId": "YOUR_NODE_ID",
  "kind": "document",
  "text": "Meeting notes",
  "mimeType": "text/plain",
  "title": "Meeting notes"
}
```

```sh
flowjoe-cli action stage_media --file input.json --json
```

**Result:** A prepared entry and stored-media information. Use the returned entry in addImageSlots or a stack verb in the SAME run list.

## Generate an image for placement — `generate_image`

Use the configured image service and its normal paid credits. The bridge allows at most two generation attempts per connection, including failed attempts; a longer run list must stay within that limit. Optional size and quality can override the app’s generation settings. A style hint applies only when the app’s Generate Images style is None. The external bridge refuses action edit with chat_history_required; to make a variation, use action generate with sourceImageKey or a caller-owned referenceAttachmentId. referenceAttachmentId uses this connection’s uploaded image; sourceImageKey targets an accessible stored image.

Select the destination node in FlowJoe before starting generation. The request keeps that destination if you select another node while it runs. A missing, removed, private or hidden destination cannot receive the generated result.

**Changes and approval:** Calls a paid service immediately; --autoapprove is not a billing confirmation. Placement is a separate Flow edit.

| Input | Required? | Meaning |
| --- | --- | --- |
| `prompt` | Yes | What to generate, or what to change when supplying a source image. |
| `action` | No | Use generate (the default). The external bridge rejects edit because it requires Joe chat history. |
| `size` | No | Image dimensions: 1024x1024 (square), 1024x1536 (portrait) or 1536x1024 (wide). Omit to use your app setting. |
| `quality` | No | Choose low, medium, high or auto. Omit to use your app setting. |
| `style` | No | Optional style hint; only used when the Generate Images tab style is None. Otherwise that tab’s selected style applies. |
| `referenceAttachmentId` | No | For an image reference, use attachment.id returned by upload_attachment earlier in this same run list. Joe-chat attachment IDs and IDs from previous CLI commands are not accepted. |
| `sourceImageKey` | No | Stored indexeddb: source key of an accessible gallery image to use for a variation with action generate. Private or hidden-from-Joe images are refused; the original remains unchanged until you place a result. |
| `title` | No | Optional title for the staged gallery entry. |

```json
{
  "prompt": "A watercolor illustration of a mountain lake",
  "title": "Mountain lake"
}
```

```sh
flowjoe-cli action generate_image --file input.json --json
```

**Result:** A staged image and prepared entry, not an automatically placed gallery item. Place the returned entry in the same run list.

For an uploaded image reference, put this step **after an image `upload_attachment` step saved
as `uploaded` in the same `run` list**. Replace `YOUR_PROMPT` with your instructions:

```json
{
  "action": "generate_image",
  "input": {
    "prompt": "YOUR_PROMPT",
    "referenceAttachmentId": {"$result": "uploaded", "path": ["attachment", "id"]}
  },
  "saveAs": "generated"
}
```

This is a run-list step, not a standalone input file. Add a later placement step using
`{"$result":"generated","path":["entry"]}`, as in the
[image-generation task example](/cli/everyday-tasks#add-a-file-or-generate-an-image). The upload must
be an accepted image MIME type; using a text upload or a previous command’s ID is refused.

## Upload an image or text file for this command — `upload_attachment`

Upload PNG, JPEG, GIF, WebP, plain text, Markdown or CSV. Current limits: 8 MB per file, 12 attachments and 24 MB total per connection. The base64 field has its own encoded-size limit. PDF, Word, audio and video are not accepted by this upload action; use request_file for the app’s normal import flow.

**Changes and approval:** Uploads to temporary connection storage; no Flow edit approval.

| Input | Required? | Meaning |
| --- | --- | --- |
| `fileName` | Yes | File name, 1–180 characters. |
| `mimeType` | Yes | Supported image or text MIME type. |
| `dataBase64` | Yes | File bytes encoded as base64, without a data: prefix. |

```json
{
  "fileName": "hello.txt",
  "mimeType": "text/plain",
  "dataBase64": "SGVsbG8="
}
```

```sh
flowjoe-cli action upload_attachment --file input.json --json
```

**Result:** An attachment with id, fileName, mimeType and sizeBytes. Read or stage it later in the SAME run list; it disappears when the command ends.

## Read an uploaded attachment or retained attachment memory — `read_chat_attachment`

Omit `mode` to read a file uploaded by this MCP connection. Upload IDs belong only to this command. With `mode: "memory"`, read retained attachment evidence from an exact admitted conversation returned by `query_history`; this never borrows whichever native Joe chat is open. Save an upload step as uploaded before the upload example below.

**Changes and approval:** Read only; no approval.

| Input | Required? | Meaning |
| --- | --- | --- |
| `attachmentId` | Yes | Upload: ID from `upload_attachment` in this connection. Memory: `*` to list, or exact memory ID returned by the list. |
| `mode` | No | Omit (or `image`) for the existing uploaded-file read; use `memory` for retained text evidence. |
| `recordId` | Memory | Exact chat `recordId` returned by `query_history`. |
| `historyRevision` | Memory | That chat record’s `revision` from `records`, not the query’s collection revision. |
| `revision` | Memory record/continuation | Exact listed memory record revision; list continuations use the memory index revision. |
| `start` | No | Returned `nextStart`: record offset for `*`, character offset for an exact memory ID; starts at 0. |
| `limit` | No | Memory index: 1–30 records; exact memory: 1–12,000 characters. |

```json
{
  "attachmentId": {
    "$result": "uploaded",
    "path": [
      "attachment",
      "id"
    ]
  }
}
```

Use this as a step in the same `run` list as its prerequisite:

```json
{
  "action": "read_chat_attachment",
  "input": {
    "attachmentId": {
      "$result": "uploaded",
      "path": [
        "attachment",
        "id"
      ]
    }
  }
}
```

**Result:** Uploaded attachment metadata plus image bytes or UTF-8 text content. Use inside a run list.

For retained attachment memory, use a query/index/read run list:

```json
[
  {"action":"query_history","input":{"kind":"chat","query":"YOUR_CONVERSATION_TEXT"},"saveAs":"conversation"},
  {"action":"read_chat_attachment","input":{"mode":"memory","attachmentId":"*","recordId":{"$result":"conversation","path":["records",0,"recordId"]},"historyRevision":{"$result":"conversation","path":["records",0,"revision"]}},"saveAs":"index"},
  {"action":"read_chat_attachment","input":{"mode":"memory","attachmentId":{"$result":"index","path":["records",0,"attachmentId"]},"revision":{"$result":"index","path":["records",0,"revision"]},"recordId":{"$result":"conversation","path":["records",0,"recordId"]},"historyRevision":{"$result":"conversation","path":["records",0,"revision"]},"limit":2000},"saveAs":"memory"}
]
```

Check that the query returned the intended admitted conversation before using its result. A missing or ambiguous conversation is unavailable. Memory results give `textContent`, source identity/provenance, revision, range and optional `nextStart`; use the same record and memory revisions for more. They explicitly say `stored_memory_not_original_bytes`. A document’s retained memory can remain readable after its original bytes are gone; unavailable or unprovable memories require existing full context or re-sharing. This grants no original-file download or image pixels.

Exact retained-memory addresses with both current revisions can be read in a new authenticated command; upload IDs cannot. Changed stored memory, conversation, privacy, Flow/storage authority, permission or cancellation refuses publication. A memory ID cannot select an uploaded file, and an upload ID cannot select retained memory. External memory reads work with native Joe Off. Native CLI brains use only their exact active turn’s conversation; guests and scheduled runs do not inherit this access.

## Control music and playlists — `control_global_player`

Control the header player. The action choices and examples below cover playback, mode and saved playlists. Accessible audio only; this is not a transcript or general media editor.

**Changes and approval:** Immediate playback/UI action; no approval card. save_playlist saves a playlist. Flow edit undo does not revert player actions.

| Input | Required? | Meaning |
| --- | --- | --- |
| `action` | Yes | What to do with the header player. Choices: show, hide, play, pause, set_mode, play_once, play_tagged, save_playlist, load. |
| `playlist` | No | Saved playlist name for action load. Exact match, case-insensitive. Do not combine with nodeId. |
| `nodeId` | No | Node id whose audio should load (load), whose one file should play (play_once), or whose tagged audio should be searched/saved (play_tagged/save_playlist with tagId). Do not combine with playlist. |
| `play` | No | With action load, true starts playback. Omit or false loads the source and leaves playback paused. |
| `mode` | No | Playback mode for action set_mode. Sequential repeats the queue in order; shuffle randomizes track order; repeat-one loops the current track. Choices: sequential, shuffle, repeat-one. |
| `slotIndex` | No | 0-based gallery slot index for action play_once. |
| `itemIndex` | No | 0-based item index inside a stack for action play_once. Required when that slot contains multiple audio files. |
| `tagId` | No | Exact visible user tag id from get_flow_snapshot's top-level tags dictionary, for action play_tagged or to save matching audio in action save_playlist. |
| `playlistName` | No | User-provided name for a new playlist saved from the current queue or tagId source, for action save_playlist. Duplicate names are refused. |

```json
{
  "action": "pause"
}
```

```sh
flowjoe-cli action control_global_player --file input.json --json
```

**Result:** Player action success/state, or an unavailable/invalid-source error.

## Music player examples

Save each input below as `input.json`, then run
`flowjoe-cli action control_global_player --file input.json --json`.

| Goal | JSON input |
| --- | --- |
| Show the player | `{"action":"show"}` |
| Hide it and stop playback | `{"action":"hide"}` |
| Play the loaded queue, or the first accessible playlist if empty | `{"action":"play"}` |
| Pause | `{"action":"pause"}` |
| Shuffle the loaded queue | `{"action":"set_mode","mode":"shuffle"}` |
| Play sequentially and repeat the queue | `{"action":"set_mode","mode":"sequential"}` |
| Repeat the current track | `{"action":"set_mode","mode":"repeat-one"}` |
| Load a saved playlist and start playing | `{"action":"load","playlist":"My playlist","play":true}` |
| Load a node’s audio, staying paused | `{"action":"load","nodeId":"YOUR_NODE_ID","play":false}` |
| Play one audio item once | `{"action":"play_once","nodeId":"YOUR_NODE_ID","slotIndex":0}` |
| Play one member of an audio stack | `{"action":"play_once","nodeId":"YOUR_NODE_ID","slotIndex":0,"itemIndex":1}` |
| Play audio with a tag | `{"action":"play_tagged","tagId":"YOUR_TAG_ID"}` |
| Save the current queue | `{"action":"save_playlist","playlistName":"My playlist"}` |
| Save tagged audio without changing playback | `{"action":"save_playlist","tagId":"YOUR_TAG_ID","playlistName":"Research music"}` |

`load` takes either `playlist` or `nodeId`, never both. `play_tagged` and tag-based `save_playlist`
can add `nodeId` to limit their search. Playlist names match exactly ignoring case, and saving
refuses duplicate names instead of overwriting them. Read real tag IDs from the snapshot.

## Supported staging kinds and file limits

The live staging catalog lists image, PDF, document, audio and video, plus spreadsheet,
rich-document and calendar kinds. **The external bridge currently cannot stage spreadsheet,
rich-document or calendar content**, including an uploaded CSV selected as kind spreadsheet.
Those importers need a file-attachment handle, while this bridge passes uploaded content to staging
as a data URL. Use `request_file` and the normal app importer for those workbench types.

The external upload action also accepts only the image/text MIME types listed above. PDF, Word,
audio and video files cannot be uploaded through `upload_attachment`; use the normal file chooser
for them. A raw `dataUrl` can prepare a supported non-workbench kind when its MIME and size are
valid; it does not bypass the workbench restriction. Do not invent an attachment ID or relabel a
file’s MIME type. Staging is preparation, not placement; see the [working example](/cli/scripting).
