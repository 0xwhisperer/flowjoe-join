title: "Change references and stacks"
description: "Edit gallery notes, organize references and stacks, crop images, and change canvas items."
---

Retained chat attachment memory and current gallery content are separate evidence sources. Use the [memory read action](/cli/action-reference#read-an-uploaded-attachment-or-retained-attachment-memory--read_chat_attachment) for saved conversation evidence; it does not recover original gallery bytes.

A repository-backed gallery file can be inspected with [read_repo_file](/cli/action-reference#read-a-repository-file--read_repo_file). The one repository change is [editRepoFileText](#change-text-in-one-repository-file--editrepofiletext): one exact text change to one existing file, held for your review unless you started the session with `--autoapprove`. No gallery verb gives terminal access, commits or pushes.

Every example below is a **separate** change. Save its JSON as `changes.json`, replace all
`YOUR_…` placeholders with IDs from your current Flow, and run:

```sh
flowjoe-cli apply changes.json --preview --json
flowjoe-cli apply changes.json --json
```

The first command checks without applying. The second follows FlowJoe’s approval rules. Add
`--autoapprove` to the second command to skip **all approval cards, including deletions**, for that
command. Permissions, privacy, frozen content and validation still apply. All verbs on these pages
change data; none is a read command. A successful patch reports applied and operation results; a
failed operation rolls back that patch. See [results and exit codes](/cli/commands#results-for-scripts).

A gallery position (`slotIndex`, `index`, `sourceIndex`, `fromIndex`, `toIndex`) starts at **0**:
0 means first, 1 means second. An `itemIndex` selects a member **inside a stack**, also from 0.
Only use examples whose targets exist and have the required content type. Examples with two or
three positions need at least that many items. Read fresh data after an edit that changes positions.

The required inputs below come from the editing catalog measured on 2026-10-19: 60 verb names for 59 distinct changes, because `setNodeReadOnly` is an older name for `setNodeFrozen` (discover the running build’s catalog for updates). Where an alternative stable entry
ID is listed, supply that instead of its positional field, not both. Read IDs with a gallery snapshot;
not every verb supports the same ID alternative. `removeEntryContexts` uses nested positional
references. The live catalog is authoritative for your installed desktop version:

```sh
flowjoe-cli action describe_patch_protocol --json
```

Prepared-entry examples containing `$result` belong **inside a `run` action list**, after a step
saved as `prepared`; they cannot be pasted unchanged into a standalone `apply` file. See the
[complete upload → prepare → place example](/cli/scripting#use-an-earlier-result). Replace that
example’s final `ops` with the operation shown here. Never invent a stored-media key.

## Move a gallery item within its node — `moveSlotWithinNode`

Move one gallery position to another. Read current positions first; both indices start at zero.

**Required inputs:** `nodeId`, `fromIndex`, `toIndex`.

**Stable IDs:** `fromEntryId` can replace `fromIndex`; `toEntryId` can replace `toIndex`.

```json
[
  {
    "verb": "moveSlotWithinNode",
    "args": {
      "nodeId": "YOUR_NODE_ID",
      "fromIndex": 0,
      "toIndex": 1
    }
  }
]
```

**Result:** The gallery order changes.

## Set the complete gallery order — `reorderSlots`

Give every current gallery index exactly once, in the desired order. This two-item example requires exactly two gallery items.

**Required inputs:** `nodeId`, `order`.

**Stable IDs:** `orderEntryIds` can replace `order`.

```json
[
  {
    "verb": "reorderSlots",
    "args": {
      "nodeId": "YOUR_NODE_ID",
      "order": [
        1,
        0
      ]
    }
  }
]
```

**Result:** The gallery takes the supplied order.

## Sort gallery items — `sortSlots`

Sort by title or number, in asc or desc order. Numbers are parsed from titles; items without numbers go last.

**Required inputs:** `nodeId`.

```json
[
  {
    "verb": "sortSlots",
    "args": {
      "nodeId": "YOUR_NODE_ID",
      "by": "title",
      "direction": "asc"
    }
  }
]
```

**Result:** The node’s gallery is sorted.

```json
      ]
    }
  }
```

**Result:** The selected gallery items are removed.

## Add prepared references to a gallery — `addImageSlots`

Despite its older name, this adds supported prepared references, not only images. Prepare entries with stage_media or generate_image in the same run list. Optional index chooses insertion position; omitted means append. The result reference in this example requires the prepared step in the scripting guide.

**Required inputs:** `nodeId`, `entries`.

```json
[
  {
    "verb": "addImageSlots",
    "args": {
      "nodeId": "YOUR_NODE_ID",
      "entries": [
        {
          "$result": "prepared",
          "path": [
            "entry"
          ]
        }
      ]
    }
  }
]
```

**Result:** The prepared references appear as new gallery items.

## Delete specific gallery or stack occurrences — `removeEntryContexts`

For precise deletion across nodes, give contextRefs with nodeId and slotIndex; add entryIndex for a stack member. This nested field is entryIndex, not itemIndex. Linked original/derived relationships are handled by the app’s deletion rules. This is a deletion.

**Required inputs:** `contextRefs`.

```json
[
  {
    "verb": "removeEntryContexts",
    "args": {
      "contextRefs": [
        {
          "nodeId": "YOUR_NODE_ID",
          "slotIndex": 0
        }
      ]
    }
  }
]
```

**Result:** The specified occurrences are removed.

**Required inputs:** `nodeId`, `slotIndex`.

**Stable IDs:** `slotEntryId` can replace `slotIndex`; `itemEntryId` can replace `entryIndex`.


**Result:** Derived copies become independent; the result includes a detached count.

## Write a reference’s title or notes — `setSlotFields`

fields accepts title, notes and audioTitle (audio only). To edit a stack member, add options with itemIndex, for example options: `{itemIndex: 0}`. An empty notes string clears notes. This edits reference notes, not the file’s stored text.

**Required inputs:** `nodeId`, `slotIndex`, `fields`.

**Stable IDs:** `slotEntryId` can replace `slotIndex`.

```json
[
  {
    "verb": "setSlotFields",

      "slotIndex": 0,

        "notes": "Reviewed for the next meeting."
      }
    }
  }
]
```

**Result:** The chosen reference fields change.

## Change text in one repository file — `editRepoFileText`

Propose one exact text change to one existing repository file. It must be the only change in its request, so send it on its own. Scheduled tasks and guest sessions cannot use it.

**Required inputs:** `nodeId`, `entryId`, `source` (`saved` or `draft`), `expectedOid`, `oldText`, `newText`. Optional: `repoNodeId`, and `draftVersion` when `source` is `draft`.

Read the file first with [read_repo_file](/cli/action-reference#read-a-repository-file--read_repo_file) using the same `source`, and copy its `oid` into `expectedOid` (and, for a draft, its `draftVersion`). `oldText` must appear exactly once in the saved file, or in the open unsaved editor draft when `source` is `draft`. A draft edit needs that repository editor tab to be open in FlowJoe; a historical revision cannot be edited. Requires Propose access.

```json
[
  {
    "verb": "editRepoFileText",
    "args": {
      "nodeId": "YOUR_NODE_ID",
      "entryId": "YOUR_FILE_ENTRY_ID",
      "source": "saved",
      "expectedOid": "YOUR_FILE_OID",
      "oldText": "retries = 3",
      "newText": "retries = 5"
    }
  }
]
```

**Result:** Held for your review on the approval card, which shows the exact before/after, even when FlowJoe’s Auto-apply setting is on — unless you started this CLI command with `--autoapprove`, which approves its changes for you. Applying saves the file in FlowJoe only; it does not write your working folder and makes no commit or push. Undo (`undo_last_change` in the same run list) restores the previous version unless the file was saved again or the open editor tab has newer typing.

`--preview` changes nothing, but for this verb it only checks the request’s shape and that the edit is sent alone. Whether `oldText` still matches the current file is checked by the approval card’s own preview (Approve stays unavailable while it does not match) and again when the change is applied. A change that no longer matches writes nothing; reject the card and propose a fresh edit. Refusals: `file_edit_must_be_alone` (immediately); `old_text_not_found`, `old_text_not_unique`, `draft_changed`, `changed_meanwhile`, `not_a_repository_file`, `editing_blocked` (the file is Frozen, Private or read-only) and `no_change` (when applied).
