Populating your gallery is designed to be frictionless. FlowJoe lets you ingest files from your local system, grab clips from your clipboard, or link directly to files on disk.

---

## Adding Files

### 1. Drag & Drop
You can drag multiple files directly from your system finder/explorer and drop them onto:
- **The Gallery Gaps:** Adds them as new slots at the end of the gallery.
- **An Existing Slot:** Adds the dropped item as a new layer in a [Stack](/gallery/stacks).
- **A Tree Node:** Adds them directly to that node's gallery, even if the node is not currently selected.
- **Supported Drops:** Individual files, folders (imported recursively), zip archives, and `.fj` packages.

When you choose several files, FlowJoe asks whether to keep **Every File Separate** or make **One Stacked Slot**. Use separate slots to compare related sources side by side; use a stack for material you want to keep together in one card.

### 2. File Pickers & Paste
- **Add Item button:** Click the grid addition card to choose files manually.
- **Clipboard Paste (`Cmd/Ctrl+V`):** Press paste while the gallery has focus to insert images, text snippets, or file paths currently in your clipboard.

## Referencing vs. Importing

When adding local files, FlowJoe offers two modes:

| Mode | Storage Location | Performance | Portability |
| :--- | :--- | :--- | :--- |
| **Import Copy** | Stored inside IndexedDB | High (copies cached locally) | Portable (packages into `.fj`) |
| **Linked Local File** | Kept in origin folder on disk | Dependent on disk paths | High disk risk (broken paths on other machines) |

### Linked Local Files
A **Linked Local File** reference points directly to an absolute path on your hard drive (e.g. `/Users/name/Projects/report.pdf`).
- **No Duplication:** FlowJoe doesn't duplicate large video or audio files, saving disk space.
- **Live Updates:** Editing the file in external software reflects instantly in FlowJoe's preview.
- **Path Warnings:** If you move the project to another computer, links will break unless the file exists at the exact same absolute path.

When you join an owner’s shared Flow in a browser, you can view its shared linked media through the owner while sharing is available. Your browser receives the file bytes without the owner’s local path. Choosing or relinking files on the owner’s disk, opening them in a native app, and revealing them in Finder or Explorer require the owner’s computer.

An Edit guest can copy a shared linked-file slot. The copy is another reference to the same file, with its own card, title and notes; it does not duplicate the file on disk. A View guest can read the shared file but cannot create the copy.

> [!WARNING]
> **Frozen Node Restrictions:** Drag-drops and file additions are disabled inside Frozen nodes and Virtual Galleries to protect structure and search results.

An Edit guest can replace a linked card’s content without overwriting or deleting the original file on the owner’s disk. Replacing their own content follows the usual contribution rules; replacing someone else’s content requires the owner’s removal permission. Private content remains excluded. Ordinary gallery uploads do not require Joe or picture generation to be enabled.

### Shared linked stacks

Edit guests can use shared linked files in new or replacement stacks, copy an individual shared stack item, merge cards, and extract items. These operations retain working references through the owner; they do not overwrite the original files on disk. Private items remain excluded, including when another item in the same stack is shared.

Converting an existing card into a stack preserves who created its original content. Creating a copy creates new guest-owned content. Removing or replacing content follows the same ordinary Edit and elevated removal rules as the rest of the shared Flow.
