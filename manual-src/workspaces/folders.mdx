Normally FlowJoe keeps your Flow in its own storage inside the app. **Workspace Folder** mode writes it to a folder you choose instead, as ordinary files you can open, copy, and back up.

<Note>
Workspace Folders are available in the desktop app.
</Note>

Media reads stay tied to the opened Workspace folder. Replacing a media folder or file
with a symbolic link does not redirect a read to files elsewhere. If a file changes during reading,
FlowJoe stops that read. Closing or switching Workspaces also stops a waiting media read from being
returned to the previous Flow. Hardlinked files still work.

## Why use a Workspace Folder?

Use a Workspace Folder when you want to choose where your Flow lives and manage its files with your
usual tools. You can:

- Keep a Flow and its media together in a folder you can find in Finder or Explorer.
- Back up that folder with your normal backup tools, or copy it to another drive.
- Move the folder to another computer and open it in FlowJoe there.
- Keep the Flow's readable data under version control with a tool such as Git.

You keep working in FlowJoe normally; saves go to the connected folder automatically.

**Local storage is enough** if you prefer FlowJoe to manage storage for you. You can still export
`.fj` packages for backups or transfers. Workspace Folders are optional, and you can switch between a
Workspace and Local storage when you choose; see [Switch between Workspace and Local storage](#switch-between-workspace-and-local-storage).

<Warning>
**Older backups are protected automatically.** When a Flow already contains private
nodes, FlowJoe preserves their full content in owner-only storage, replaces it in the Workspace with
redacted placeholders, and verifies the saved file before resuming saves. A copy shared or backed up
before migration cannot be recalled. If an older Workspace backup still contains private text,
FlowJoe does the same to that backup: your private notes stay safe on this computer and the backup keeps
a placeholder. A backup that is damaged and cannot be checked is removed. Saving then resumes and a
notice tells you what was done.
</Warning>

## Where to find it

Open **Settings → Data** and look for the **Workspace Folder** card. Everything below happens there; there is no File menu entry or context-menu item for this.

On first launch, the desktop app offers **Keep FlowJoe local**, **Workspace Folder**, and **Decide later**. Choosing Workspace Folder takes you to this card to select or create the folder. If you skip onboarding, the card remains available in Settings.

---

## Setting one up

The card shows different buttons depending on whether a folder is connected.

| Button | When you see it | What it does |
| :--- | :--- | :--- |
| **New Workspace** | No folder connected | Pick an empty folder. FlowJoe copies the current Flow and all its media there, then starts saving there. |
| **Connect Workspace** | No folder connected | Open a folder that is already a FlowJoe workspace. |
| **Reconnect Workspace** | FlowJoe remembers your last folder | Reconnects to it without picking again. |
| **Change Workspace** | A folder is connected | Switch to a different workspace folder. |
| **Switch to Local Storage** | A folder is connected, or FlowJoe is temporarily saving locally | Copies the workspace back into the app's own storage and keeps editing there. The folder is left untouched. |
| **Disconnect Workspace** | A folder is connected | Detaches from the folder without taking a copy of your Flow. Editing stays paused until you reconnect the folder or start a new Local Project. To keep working with your Flow, use **Switch to Local Storage** instead. |
| **Delete Workspace** | A folder is connected | Removes only the files FlowJoe manages in that folder. This cannot be undone. |
| **Reveal Workspace Folder** | A folder is remembered | Opens the folder in Finder or Explorer. |

When you create a workspace, FlowJoe shows its progress — *"Preparing workspace…"*, then *"Copying media 3 of 12…"* — and you can **Cancel** partway through.

One Flow lives in one folder. **New Workspace** is hidden while you are already connected.

**Delete Workspace** needs free space on the drive of about the size of the workspace, because FlowJoe first makes a temporary safety copy inside the folder. If cleanup fails afterwards, a leftover folder whose name starts with `.flowjoe-delete-` may remain. Once FlowJoe has reported the delete as finished, or has put the Workspace back, that folder is safe to delete. Otherwise it may hold the only copy of your Workspace, so leave it alone and open the folder in FlowJoe first; FlowJoe tidies it up when you do. If FlowJoe is closed or crashes in the middle of a delete, the next time you open that folder FlowJoe puts the Workspace back exactly as it was and tells you; delete it again if you still want to. Any `flow.unreadable-` files (see below) are not removed.

The card shows the current Flow name, the selected or last-known folder path, and whether that folder is connected. Before connecting to an existing folder, FlowJoe summarizes both versions and calls out missing media references separately from files not used by the current Flow. The review makes no changes; Workspace media is not deleted automatically.

## What lands on disk

```
My Project Folder/
├── flow.json        Your whole Flow — tree, notes, tags, summaries — as readable JSON
├── media/           One file per image, audio file, video, and document
└── .flowjoe/        FlowJoe's own bookkeeping
```

**`.flowjoe/`** holds backups (FlowJoe keeps the newest 20), a shareable change journal, and small per-computer notes. Each note contains that computer's name and a timestamp, refreshed about once a minute while the workspace is open, so other computers can tell it is in use. If the folder is synced or shared, those notes travel with it. Version History and restore points stay with the app on this computer.

**`flow.json`** is plain, indented JSON, so a version-control tool like Git can diff and merge it as text.

**`media/`** holds your files one per item. They are named by FlowJoe's internal id and carry no file extension, so treat this folder as storage rather than a gallery to browse.

Ordinary Joe conversations and their picture backups travel with the folder. A conversation marked **Keep on this computer only**, and conversations belonging to private nodes, stay on this computer. Joe Memories, standalone Image History prompts, your preferences, and browser data also stay local. Scheduled tasks (automations) and your custom placeholder picture travel with the Flow.

Edit `flow.json` outside FlowJoe only if you know the format. If a Git merge leaves conflict markers in it, FlowJoe cannot open the workspace until you clean them out. If it becomes unreadable while the workspace is already open, see the next section.

## Backups, Git, and syncing

Back up a Workspace Folder like any other directory: Time Machine, an external drive, or a sync client. Git can track the folder too, but that tracks the Flow's storage files together; it is not how FlowJoe's project repositories work.

### Move a Flow to another computer

1. Let the Flow finish saving, then close FlowJoe on the source computer.
2. Copy the whole Workspace folder, including `flow.json`, `media/`, and the hidden `.flowjoe/` folder,
   to a local drive on the other computer.
3. On that computer, open **Settings → Data → Workspace Folder → Connect Workspace** and select the copied folder.

Private nodes and conversations marked **Keep on this computer only** stay on their original
computer. Version History and restore points also stay with that computer's app storage. Copying a
Workspace moves its folder content; it does not move all of FlowJoe's settings and local history.

<Note>
A **Workspace Folder** chooses where the Flow's data is stored. A **repo node** gives one node its own Git repository for project files. Those are separate choices: repo-node files appear in the node tree and galleries and are saved through FlowJoe's normal storage, while Git history is kept as FlowJoe-managed hidden data.

To bring a project into Git in FlowJoe, create or clone a repo node from the New Node window. Do not make the whole Flow's Workspace Folder the project repository.
Each repo node has its own hidden Git history; its files remain in the Flow's tree and galleries. See [Repo nodes and Git](/tree/repositories) for HTTPS and SSH remotes.

</Note>

### iCloud Drive, Dropbox, and Google Drive

You can choose a Workspace Folder inside a folder managed by the desktop app for iCloud Drive,
Dropbox, or Google Drive. FlowJoe reads and saves the files through your computer's filesystem;
the sync service copies changes to and from the cloud in the background. FlowJoe does not need a
separate cloud connection or upload your Workspace through those services' APIs.

Keep the **whole Workspace folder** downloaded, including `media/` and `.flowjoe/`, so the files
remain available while you work:

- **iCloud Drive:** in Finder, select the folder and choose **Keep Downloaded** where available.
  See [Apple's iCloud Drive guide](https://support.apple.com/guide/mac-help/work-with-folders-and-files-in-icloud-drive-mchl1a02d711/mac).
- **Dropbox:** choose **Make available offline** for the folder.
  See [Dropbox's offline-files guide](https://help.dropbox.com/sync/access-files-offline).
- **Google Drive for desktop:** use **Mirror files**, or make the Workspace folder **Available offline**
  when using streamed files. See [Google's stream and mirror guide](https://support.google.com/drive/answer/13401938?hl=en).

A file left online-only may need downloading before FlowJoe can read it. Google Drive's streamed
files may appear on a virtual drive; they are still checked through the filesystem like other
Workspace folders.

**Saved in FlowJoe** means the files were saved in the selected folder. It does not mean the sync
service has finished uploading them. Before moving to another computer, finish saving, close the
Workspace on the first computer, and wait for syncing to finish on both computers before opening
it on the second. Editing on two computers before their files have synced can produce competing
versions; FlowJoe's outside-change review helps you choose between them.

The folder paths and conflict-handling code support this arrangement. This does not claim that all
three services have been verified in live end-to-end tests.

### Network and shared drives

You can use a Workspace Folder on a network or shared drive. Connect the drive through Finder or
Explorer first, sign in there if needed, then select the folder in FlowJoe. On Windows, a mapped
drive or a UNC folder path can be used. A server address such as `smb://server/share` needs to be
connected through your computer before you select its folder.

FlowJoe checks that it can write and replace files in the folder before connecting. A network-drive
label alone does not prevent connection. If the checks fail, fix the reported access or drive problem
and try again.

FlowJoe checks periodically for outside changes as well as listening for file-change notifications,
so a drive that does not send those notifications can still be used. Outside changes may take about
15 seconds to appear. Saving also checks for outside changes before replacing the saved Flow.

If the drive becomes unavailable or refuses a save, FlowJoe continues saving locally and reconnects automatically when it can. See [Switch between Workspace and Local storage](#switch-between-workspace-and-local-storage)
for the available recovery choices. Network devices vary; passing the checks does not certify every
device's behavior during a power cut or connection failure.

If a sync service (Dropbox, iCloud Drive, Google Drive, OneDrive) leaves a conflict copy of `flow.json`
in the folder, FlowJoe notices it and tells you.

Replacing files inside `media/` by hand is not a supported way to swap media — FlowJoe watches `flow.json`, not the media folder.

## When something changes outside FlowJoe

If `flow.json` changes on disk while FlowJoe is running — a sync client pulling a newer copy, or you editing it directly — FlowJoe tells you rather than silently picking a side.

If the change does not collide with your work, it refreshes on its own (and tells you when the change turns up while you are saving), and any unsaved edits to your unlocked private nodes are kept. If it does, you get **Someone changed this Workspace file outside FlowJoe** and choose:

- **Use External Changes** — take the version on disk. Your own version, including any private nodes you have unlocked, is kept as a complete copy on this computer only. If the file changes again while FlowJoe is taking it, you are asked again instead of the newer file being accepted unseen.
- **Keep My Changes** — keep what is in FlowJoe and overwrite the file.
- **Open External as New Flow** — open the disk version separately and decide later.
- **Decide Later** — close the dialog without choosing. Folder saving stays paused, the status bar shows **Outside change waiting · saving paused**, and clicking it reopens the dialog. Edits you make meanwhile are kept on this computer and saved to the folder once you decide.

### When the workspace file can't be read

If `flow.json` becomes unreadable while the workspace is open (a Git merge left markers in it, a hand edit broke it, or it is too large), FlowJoe shows **FlowJoe can't read the workspace file**. Your work stays safe in FlowJoe. You can:

- **Check Again** — after you fix the file.
- **Keep My Changes** — FlowJoe first saves the unreadable file next to it as `flow.unreadable-<date>.json`, then saves your version.
- **Decide Later** — leave saving paused for now.

### Open on another computer

If the workspace was used on another computer within the last 5 minutes, FlowJoe warns **This Workspace is open on another computer** before you open or reconnect it, and when you reconnect it. Choose **Open here anyway** or **Cancel**. Automatic return waits while another computer is using the folder; your work continues saving locally. Cancelling an explicit reconnect leaves your current Local work available. While both computers have it open, the status bar shows **Also open on (computer name)**. Editing on two computers at once can leave two different versions of your Flow.

### Missing, retained, and changed media

- A missing media reference is listed separately; FlowJoe does not replace it with a different file.
- Files present in the folder but unused by the current Flow are counted and retained; Workspace media is not deleted automatically.
- **Settings → Data → Inspect Stale References** shows missing targets and any safely repairable metadata. Safe repairs remove only the stale metadata link; they do not delete media files.
- If FlowJoe detects that a media file changed after it was read, it stops the write and opens the existing review path. The outside copy is preserved until you resolve the review.

## Using one Workspace on two computers

If two computers, or two FlowJoe windows, save the same Workspace at the same moment, FlowJoe lets one finish first and the other waits a few seconds, then saves. Nothing you type meanwhile is lost.

If a sync service delivers a version that was made without your latest save, FlowJoe asks which version to keep and keeps a copy of the other one.

After launch, FlowJoe opens your verified Local copy while it checks the folder. Independent changes
can be combined automatically; conflicting changes leave your Local work saved and available for
review. Explicitly opening a changed folder can also preserve your previous version as a copy listed
in Settings.

The **Open on another computer** note is only information. It never stops you from opening or saving.

## When a folder becomes unavailable

<Frame caption="You can keep working during a temporary folder outage. Review conflicting changes before deciding what to keep.">
  <img src="/images/diagrams/workspace-recovery.svg" alt="When a folder becomes unavailable, work saves locally; on its return FlowJoe checks changes and either resumes safely or asks for conflict review." />
</Frame>

If the drive disconnects, the folder refuses a save, or its disk fills up, FlowJoe automatically
continues saving your current Flow on this computer. You can keep editing. The status bar says
**Saving locally · reconnecting automatically**; you do not need to switch storage or answer a
recovery prompt for an ordinary temporary outage.

When the same folder is available again, FlowJoe checks it and saves your latest Local work back
before resuming folder saving. Independent edits in the folder are combined with your Local edits
when they can be kept safely. It keeps your newer edits rather than opening an older folder copy.
This also works after restarting FlowJoe while the folder is still unavailable.

If the folder contains conflicting changes, your work stays saved locally while you review the
versions. FlowJoe does not guess which work to discard. A replaced folder or a different Workspace
or Flow needs an explicit reconnect.

Choosing **Switch to Local Storage** deliberately stops automatic return. Choosing another Flow or
Workspace also stops the old folder from taking over later. Ordinary Local saving and closing the
app do not wait for a disconnected drive.

Automatic recovery needs a usable Local copy and enough space on this computer to save your work.
If neither destination can save, FlowJoe tells you and retains the work it can recover rather than
claiming it is saved. The explicit recovery tools remain available for an incomplete or damaged copy.

Your ways out, all on the same card:

- **Reconnect Workspace** — reconnect once the drive is back.
- **Use Local Copy** — continue from FlowJoe's own recent copy of your work.
- **Rebuild Workspace** — write the workspace out to a new folder.
- **Switch to Local Storage** — go back to the app's own storage.
- **Start New Local Project** — begin a fresh Flow.

FlowJoe keeps a **Local Recovery Copy** inside the app while you work in a workspace, which is what **Use Local Copy** restores from. See [History & Recovery](/workspaces/recovery).

If a save was interrupted halfway, connecting reports it and offers **Clear Interrupted Save**. FlowJoe only clears saves it can prove never completed; anything else it leaves alone and tells you so.

If a save from another computer never finished in this folder (for example it was switched off mid-save), Settings shows **A save from that computer never finished. It isn't part of your Flow.** FlowJoe waits a couple of minutes first, in case the other computer is still saving. This computer never applies another computer's unfinished save, so your Flow is never replaced by it. The card offers one action, **Clear**, which asks you to confirm and then deletes the leftover. Your Flow stays exactly as it is.

If it was your own other computer, open FlowJoe there before clearing: it finishes its own interrupted save, as long as nobody has saved this Flow since. If someone has, that save is dropped there too.

## Switch between Workspace and Local storage

You can go back and forth using **Settings → Data → Workspace Folder**. Only one location receives
your Flow's saves at a time.

1. **Workspace → Local:** choose **Switch to Local Storage**. FlowJoe saves pending work, copies the
   Flow and its media into the app's storage, and continues there. The Workspace folder is left intact.
   Use this rather than **Disconnect Workspace** if you want to keep editing the same Flow.
2. **Work locally:** new edits save inside FlowJoe. They do not update the disconnected folder.
3. **Local → Workspace:** choose **Reconnect Workspace** for the remembered folder, or
   **Connect Workspace** and select the original folder. If you edited the Local copy, review how
   those edits should return to the Workspace using the choices below.

If saving to the folder has failed but FlowJoe can still read it, **Switch to Local Storage** keeps
what is currently on screen, including the latest edit that could not be saved to the folder. It
checks that the Local save succeeded before completing the switch. If the folder cannot be read,
use the recovery choices under [When a folder becomes unavailable](#when-a-folder-becomes-unavailable).

You can repeat this process. Returning to a folder after Local edits can require a decision about
which version to use. FlowJoe does not continuously sync the two locations. If a required save or
safety copy cannot finish, the switch stops and reports the problem.

### Reconnect after working locally

If you edited a Local copy before reconnecting, FlowJoe asks how to bring the two versions together:

| Choice | What happens |
| --- | --- |
| **Keep Workspace** | Open the folder’s version and keep the differing Local version separately. |
| **Send My Changes** | Write your Local version into the folder. |
| **Merge Safe Changes** | Add Local changes that do not conflict. Where both versions changed the same work, keep the folder’s version. |
| **Keep as Separate Flow** | Preserve your Local work as its own Flow. |
| **Not Now** | Leave both versions unchanged. |

Find preserved versions under **Settings → Data → Retained Reconcile Flows**. Export one before removing it if you want a portable copy.

See [History & recovery](/workspaces/recovery) for a different recovery prompt that offers **Keep Workspace**, **Use Local Copy**, or **Rebuild Workspace**.

## Private nodes

Private-node passwords control access inside FlowJoe; they do not encrypt the local saved content or media. A password-protected `.fj` export encrypts that exported copy only. Opening it restores normal app storage and retains each Private node’s separate password. See [Encrypted backups](/concepts/security#encrypted-backups).

Workspace files represent password-protected private nodes as *"Private node (not shared)"*
placeholders. When you create one in a Workspace, FlowJoe keeps it out of the live Flow until
protection and its device-only copy are confirmed; only then can it be saved to the Workspace. When
opening an older Flow, FlowJoe first confirms a durable owner-only copy before running load-time
migrations, then checks the Workspace file before normal saving resumes. If FlowJoe cannot confirm
that local copy, the connection stops before hydration or saving. Copies made before migration may
remain elsewhere and cannot be recalled. If a retained Workspace backup still contains private
text, FlowJoe replaces that text with a placeholder (your private notes stay on this computer) and
removes any backup too damaged to check, then lets saving resume.

Pictures and files you add to a private node are kept on this computer — FlowJoe does not put them
in the Workspace folder itself, and guests cannot load them. If the node stops being private (for example, you
remove its password), FlowJoe copies its pictures into the folder the next time it saves.
This also holds when you open a `.fj` file (File > Open, Recent imports or Import Node(s)) while a Workspace is connected: pictures and files that belong to its private nodes stay on this computer, and only the rest goes into the Workspace folder. These protections also apply when you drop a `.fj` file onto the tree. Its private nodes retain their passwords, and their files stay on this computer. Importing into a private node makes the imported branch private too; FlowJoe asks first.

Pictures and files that private nodes put in the Workspace folder before this protection existed are moved to this computer automatically the next time you open the Workspace, once an identical copy is safely on this computer. They keep working for you, and the folder no longer holds them. A spreadsheet, document or calendar of a private node that you have edited since may still have an older copy in the folder; FlowJoe leaves that copy in place so your newer version is never lost. Copies that other computers, sync services or backups already made cannot be recalled.

FlowJoe confirms that private edits are safely saved on this computer before marking a Workspace
save complete or switching to another Workspace. If that local save fails, saving pauses and the
switch stops so the latest private edits are kept with the current Flow.
When you delete the last private node, a completed save also updates this Flow's local startup
recovery copy and removes the deleted node's old private copy so it does not return when you reopen
the Flow. If the folder save or that local cleanup fails, saving pauses and the earlier private copy
stays recoverable. A recovery copy belonging to another Flow is left alone.

A private node's content stays on the computer where it lives. It is not stored in the Workspace folder, so it does not follow you to your own second computer: there, the node appears only as the *"Private node (not shared)"* placeholder.

## Quitting FlowJoe

When you quit or close the window, FlowJoe closes straight away if nothing needs to finish. If it has to wait, a **Closing FlowJoe…** cover shows while FlowJoe saves your work and stops any running terminals (it waits about 2 seconds, then force-stops them); the cover appears at once when terminals are running, or after a moment if a save is still going. If the last Workspace save could not finish, FlowJoe tries to keep those changes on this computer
for recovery at the next start. If it cannot confirm they are safely stored, it tells you and offers
**Retry**, **Stay open**, or **Close anyway** / **Quit anyway**. Choosing to leave anyway closes the
app even if its extra recovery record cannot be written; the warning explains that unverified
changes may be lost. A failed save does not force you to keep the app open indefinitely.

## Exports still work

Workspace mode does not replace `.fj` export. You can still export a full `.fj` package or JSON at any time — see [Export & Import](/portability/export-import). Restore points are **not** included in a workspace folder or a `.fj` file; they live with the app on this device.

## Placeholder

When reconnecting a Local copy, **Merge Safe** keeps your custom placeholder replacement, on/off
change, or removal alongside an unrelated node edit in the folder. If both copies changed
Flow-wide settings, the folder's version stays in the merged result. Available placeholder picture
files are copied with the merge; a missing picture does not prevent saving.
