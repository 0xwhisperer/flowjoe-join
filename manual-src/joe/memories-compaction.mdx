Long conversations can use more of the AI model’s context and cost more to resend. FlowJoe manages them automatically, while keeping manual summary compaction available.

The token bar at the bottom of the Joe panel also shows **Flow map**, **Location**, and **Slot data** as separate slices. To shrink the tree outline Joe is given each turn — **Limit map to my location** and **Omit entire flow map** — see [Token usage with Joe](/joe/token-usage).

## Token bar

At the bottom of the Joe panel is a segmented **token bar**:
- **Visualization:** Shows how this send is partitioned using the same labels as the legend: Joe system, Tools, Flow map, Location, Slot data, FlowJoe manual, Joe Memories, Compacted Memory, Chat messages, Attachments, Estimate buffer.
- **Cost chips:** Every message displays its token footprint (e.g. `+150 tok/send`). Pinned, omitted, or deleted messages update the bar instantly.

The **Flow map** slice is the tree outline plus your Flow Summary. That is the slice **Omit entire flow map** removes. Full detail: [Token usage with Joe](/joe/token-usage).

## Manage long chats

<Frame caption="Automatic management stays on; choose summary compaction when you prefer it.">
  <img src="/images/joe/long-chat-settings.png" alt="Settings → Joe AI shows automatic long-chat management on and Use summary compaction instead off." style={{maxWidth: "520px", width: "100%"}} />
</Frame>


**Manage long Joe chats automatically** is on by default in **Settings → Joe AI**. On supported connections, Joe keeps recent messages and pinned turns in context and looks up relevant older messages from the same conversation when needed. Older message labels say **available on demand**. Your full conversation remains saved and readable.

To prefer the existing summary method, turn on **Use summary compaction instead**. Connections without conversation lookup keep using summaries. A summary you edited, or created with a custom compaction instruction, also stays in summary mode until you deliberately clear that memory. Changing the setting does not delete your conversation.

Lookup is available in the owner's API-key chats and supported desktop CLI connections with Read or Propose access. CLI connections without a conversation-reading bridge, CLI Flow access set to Off, and guest/shared transport paths retain summary management. These paths keep their existing capabilities; they do not claim the same token saving. Joe does not gain access to other conversations or more Flow content through this setting.

**Compact Older Turns** always creates a summary. You can add an optional instruction, such as “Keep the exact budget and the cancelled tasks.” **View**, **Edit**, **Regenerate** and **Delete** continue to manage saved summaries.

If older source messages become unavailable or change during a continuation, Joe does not claim to have recovered them. A lookup can take additional model requests, so it is not guaranteed to be faster or cheaper on every task.

### Memories still work

Your **Joe Memories** keep applying at their Flow, Node or Slot scope. Pinned messages stay in context, and omitted messages stay out. Reading an old message never approves an old proposal or restarts a cancelled action.

**Create attachment memories** controls new saved descriptions of pictures and documents. Older-message lookup includes the descriptions already saved with those messages. A description is not the original picture or document; re-share the original when Joe needs details it cannot recover. Turning off new attachment memories does not delete existing ones.

## Transcript Control: Pin & Omit

- **Pin for Joe:** Keeps a specific message verbatim forever. It will never be folded into a compaction summary.
- **Omit from Joe:** Temporarily drops a message from AI uploads while leaving it visible in your user transcript.
- **Attachment Memories:** When large images or documents are compacted out of verbatim history, Joe distills a permanent text summary (e.g. a layout description for a mockup). This summary carries forward so you don't need to re-upload massive image bytes on every follow-up question.

Joe checks that a background attachment summary still belongs to your conversation before starting or retrying it. If you leave or replace that conversation, work that has not yet been sent is skipped. When you regenerate an attachment memory, Joe also checks that the original attachment and conversation are still current. A late result cannot replace a newer memory edit or a newer saved conversation.

On OpenAI, Gemini, Anthropic and xAI API-key brains, attachment summaries have a 30-second request limit. An empty, cut-off, refused or invalid answer is not saved as memory: an image summary is skipped, while a document can keep a clearly marked metadata-only description. OpenAI summary requests disable response storage; FlowJoe keeps its attachment memories locally. For readable text and extracted document text, OpenAI uses Luna 6 to create the saved summary. In an eight-document comparison it preserved the checked facts and uncertainty with lower estimated helper cost and a shorter median wait. Image summaries also use Luna 6, with a little thinking switched on, which in a check of seven real photos and artworks cost roughly a quarter as much while keeping what was visible and what was uncertain. PDFs and other files sent in their original form now use Luna 6 too, with its extra thinking off. In a check of six small test PDFs (a table, a chart, two columns, a scanned page, a Spanish memo with a provisional date, and a form with empty fields) it kept every checked fact and every blank or unconfirmed detail, cost about a third as much and answered faster. Your existing and edited memories stay intact.

## Ask about an earlier attachment

In the owner's Joe chat, a brain that supports Flow tools can read an attachment's saved memory
with **Read** or **Propose** access. Repeated filenames stay separate, and a saved document memory
can remain readable after its original file bytes are no longer in the chat. Your edited memory,
warning notes and pins stay attached to that record.

Saved memory is a summary of the attachment. For exact quotations or details it does not contain,
re-share the original or the relevant section. This attachment-memory reader is separate from automatic long-chat retrieval. Recent and pinned material follows its normal send rules; older saved descriptions remain available with their original conversation messages.

## When a chat gets too large to compact automatically

If you've edited the saved summary yourself, automatic compaction never throws your edit away — it extends your summary with newer turns instead of silently rebuilding from scratch. If a conversation genuinely can't be compacted further and a send would be too large to go out, FlowJoe refuses that send with a plain message rather than shipping it and letting the provider reject it later — open **Compact Now** to review or regenerate the summary, or start a new conversation. If the model itself rejects a message as too long, FlowJoe offers a one-click **Compact now** right there in the error.

## Save a memory for later

<Frame caption="A proposed style memory for this game. This capture shows the draft editor before Save memory.">
  <img src="/images/joe/memory-draft.png" alt="The real Add Memory editor contains a draft style instruction about a lantern silhouette and warm active glow." />
</Frame>

Open **Memories** in Chat and choose **Add memory**. Write what Joe should remember, choose whether it applies to this Flow, this node and its descendants, or this slot, then **Save**.

To keep part of a reply, select the relevant words and choose its brain-shaped **Remember this** button. Review the text and scope before saving. In **Memories**, switch a memory off to stop sending it without deleting it, or edit or delete it.

Saved memories are separate from the summary of a compacted conversation. A memory can help across conversations; compaction preserves the context of one conversation.

## Joe Memories: which ones are actually sent

Joe Memories are sent up to a per-turn cap (a handful per flow, node, and slot). If you have more active memories than the cap for where you are, the Memories panel marks the ones that are past the limit with a **Not sent — over the limit** badge — pin one, or disable an older one, to make room. A memory whose node is currently private or hidden from Joe shows a separate **Not sent — Joe can't see this node** badge instead, since that one is never sent regardless of the cap. When you ask Joe to remember something very similar to an existing memory, he's told about the near-duplicate so he can mention it rather than silently creating a copy.

Remembering and recalling memories works the same way in every language FlowJoe ships (see [Language settings](/reference/settings-map)) — asking Joe "what did we decide about the budget?" in Chinese, Arabic, Thai, or any of the other 16 languages finds the same relevant memory it would in English, instead of only working for space-separated Latin-script text.

Compaction uses your selected provider: the configured small model for OpenAI, Gemini 3.5 Flash-Lite on the Gemini API key, or your selected command-line provider's helper model. Attachment memories are written on OpenAI and on the Gemini API key alike; on Gemini they use your Gemini key and nothing is sent to OpenAI. Changing providers while compaction is running affects the next job. Login (command-line) brains keep file memories too, using their own helper model on your plan with no API key. Claude Code and Codex remember your pictures, text documents and PDFs (a PDF with no readable text is read from its first pages as pictures). Grok remembers pictures, text documents and PDFs that have readable text, but not scanned PDFs yet. On a Mac, Antigravity also remembers pictures and the first pages of scanned PDFs. It reads those pictures from a private temporary folder that FlowJoe deletes after the reply finishes or stops. On Windows and Linux, Antigravity remembers readable text only. If a helper run fails, no memory is saved for that file; send the file again to try again. The Regenerate button in the memory panel works the same way, so you do not need an API key for it on a login brain.

Each API request used to compact a conversation has a one-minute limit, including reading the answer. A longer conversation may need several requests. If a request times out, FlowJoe keeps your existing history and memory and does not save a late summary. Refused, non-final or invalid summary answers are not saved either. An answer cut off at the token limit can still use the existing single retry with a larger allowance.

If Joe needs to compact before sending your message, **Stop** also stops that compaction. Joe keeps your existing history and memory; a late summary from the stopped job is not saved.
