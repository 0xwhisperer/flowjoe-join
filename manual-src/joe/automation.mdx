FlowJoe features a powerful **Background Scheduler** that allows Joe to run automated task loops on a repeating schedule. If you want to refresh a node's research links every morning, rotate reference images on an interval, or audit a campaign checklist weekly, you can write the rule once and let Joe execute it in the background.

---

## How Scheduling Works

A scheduled task gives Joe instructions to repeat while you work. He can read the outline, search the web, generate images, update notes, and manage tags using the available tools and permissions.

> [!IMPORTANT]
> Schedules run while the owning Flow is open in FlowJoe and **Scheduled runs** is enabled. Closing the app or browser stops them. A missed occurrence normally runs when you reopen the Flow, unless the task is set to skip it. FlowJoe does not replay every missed interval in a burst.

---

## Schedules created by guests

An Edit guest's scheduled task runs on the owner's computer within the area currently shared with that guest. It uses the normal scheduler tools and approval rules: no separate six-action list, URL-only restriction or guest-only ban on web search, images or shared memories. Current image-generation permission still applies. Removal follows the same creator and elevated-removal rules as other guest edits.

When a guest edits a shared task, including one created by you or another guest, its future runs use the editing guest's current shared access. The original creator still controls its ordinary removal rights.

Execution stops if the guest loses Edit access, the invitation ends, sharing pauses, the owner is presenting, or Joe is disabled for that invitation. The guest's retained shared history stays readable when new Joe requests are disabled.

Guests use the same **Tasks** settings tab. View guests can inspect shared tasks, proposals and recent runs. Edit guests can pause or resume shared tasks and approve or reject shared proposals; Run Now uses the guest's current shared access even for an owner-created task. Joe must be enabled to run or approve. The owner's global background-runs switch remains visible and locked.

Deleting tasks, review items or run history follows the same creator and elevated-deletion permission as other shared content. Clearing a mixed list keeps protected records and explains what remained. **Ask owner to restore** sends the owner a request to undo a run; it does not roll back the Flow from the guest's browser. Private task targets and private run/proposal content stay hidden.

## 📅 Scheduling Cadences

FlowJoe supports three repeating cadences for automations:

1. **Daily:** At a chosen time and timezone—for example, every morning at 8:00.
2. **Weekly:** On a chosen day and time—for example, Friday at 17:00.
3. **Interval:** Every chosen number of minutes—for example, every two hours.

For short intervals, the interface shows an estimated number of runs per day to help you understand ongoing AI usage.

## 🛠️ Task Creation & Management

You can configure and manage scheduled tasks in two ways:

* **Natural Language Chat:** Ask Joe: *"Search the web for new references on quantum computing and update my Research node every morning at 9:00 AM."* Joe will draft a proposal card showing the task parameters. Approving the proposal card registers the task.
* **Settings → Tasks:** View tasks, pause or resume them, delete them, and inspect recent results. **Run Now** means “run and apply this now,” including for a review-first task. Review-first controls unattended scheduled runs; your click authorizes this manual run without a second approval step. Changes held by the safety checks still go to **Review Inbox**.

---

## 🛡️ The Safety Seatbelt

To prevent an unattended background run from clobbering your outlines due to an AI hallucination, FlowJoe wraps automations in a **Safety Seatbelt**:

- **Auto-apply is the normal starting choice:** Approving a recurring task normally authorizes its routine updates to apply automatically.
- **Review-first is available:** Ask Joe to make the task review-first if you want results held in **Settings → Tasks → Review Inbox**.
- **Risky changes are held:** Removing nodes, tasks, or other content; changing tasks or memories; and revealing content hidden from Joe can send a result to review. TypeSafe can also hold a change that falls outside the task’s instructions.

<Note>
For an owner-created task, approving a result held by the destructive-change check also authorizes **that task** to make destructive changes on future runs. This lets a recurring task keep doing its approved work without asking the same question each time; there is no extra authorization prompt after approval. A review-first task still sends its unattended scheduled results to the inbox. Approving a TypeSafe instruction warning does not grant the broader permission, and guest-created tasks do not gain it through this approval.
</Note>

Each scheduled run has its own **Undo** in the run history, separate from your `Cmd/Ctrl+Z` in the tree — undoing a run never touches your own manual edits. If the revert itself can't be saved (for example, a storage problem at that moment), FlowJoe tells you so with a warning instead of quietly showing "undone" for a change that may come back after a restart.

## Which items a task can refresh

When you ask a task to refresh existing references—for example, “keep these news links up to date”—it needs permission to replace the old results. An owner-created task takes over the existing slots it manages on its target node, and the approval card tells you how many. Cards already managed by another task are left alone. Review that count before approving. This lets the task refresh the board from its first run.

If you ask it to keep a particular slot updated, the task follows that same slot when cards are reordered. You do not need to maintain slot numbers by hand.

## 💡 Real-World Examples

### Example 1: Daily News Aggregator
* **Prompt:** *"Every morning at 8:30 AM, search the web for the latest wargame rules balancing updates and replace the links under my rules-balance node."*
* **Configuration:**
  - **Cadence:** Daily at 08:30
  - **Web Search:** Enabled
  - **Behavior:** Adopts existing slots on creation; swaps them with fresh web cards every morning.

### Example 2: Interval Mood Board Generator
* **Prompt:** *"Every 180 minutes, generate a new retro-futuristic sketch reference and place it on my concept-art node."*
* **Configuration:**
  - **Cadence:** Interval (every 180 minutes)
  - **AI Actions:** Calls the image generation tool to write a new slot.
  - **Seatbelt:** Non-destructive (applies directly without prompt).

### Example 3: Weekly Project Auditor
* **Prompt:** *"Every Friday at 5:00 PM, scan my project milestones and report any In Progress nodes with empty summaries."*
* **Configuration:**
  - **Cadence:** Weekly (Friday at 17:00)
  - **Behavior:** Reports incomplete summaries so you can decide what to add.

Shared tasks can change a parent's status when all affected descendants are shared and editable. A parent change that would modify private or frozen descendants is refused.

When an Edit guest asks Joe to create or change a shared recurring task, the task is saved on the owner's Flow. Joe reads the owner's shared task list; tasks aimed at private content are excluded. Removing tasks follows the same creator and elevated deletion permissions as the Automation panel.

If a guest asks Joe to undo a change, Joe sends the owner a restore request. The owner performs the restoration.
